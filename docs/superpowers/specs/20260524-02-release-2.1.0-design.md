# release/2.1.0 リリース準備 設計書

## 目的

`develop` に積み上がった 168 コミット (2.0.1 以降) を 2.1.0 としてリリースするための準備作業 (version bump・CHANGELOG ヘッダ確定・README 見出し確定) を行う。本作業のスコープは「リリース準備」までで、`develop` や `master` へのマージ・PR 作成は含まない。

## 背景

- 現行バージョンは `package.json` 上 `2.0.1`。最後に `master` にリリースされたのは 2.0.1 (2026/04/14)。
- それ以降 `develop` には以下のユーザー影響変更が入っている。CHANGELOG / README は各フィーチャー投入時に逐次追記済みで、現在は「`X.Y.Z (YYYY/MM/DD)`」「`### X.Y.Z`」という暫定見出しで内容が確定済みの状態。
  - **Breaking:** Raw HTML サニタイズの既定有効化 (`markdown-pdf.sanitize`, 既定 `"gfm"`) [#411](https://github.com/yzane/vscode-markdown-pdf/issues/411)
  - **Add:** `` ```plantuml `` フェンスドコードブロックサポート [#92](https://github.com/yzane/vscode-markdown-pdf/issues/92) [#162](https://github.com/yzane/vscode-markdown-pdf/issues/162) [#389](https://github.com/yzane/vscode-markdown-pdf/issues/389)
  - **Add:** Chrome Stable 自動ダウンロード + `markdown-pdf.chromium.autoDownload` 設定
  - **Add:** KaTeX による数式描画 + `markdown-pdf.math.enabled` / `markdown-pdf.math.katex.macros` 設定
- 本リリース準備では、暫定見出しを `2.1.0 (2026/05/24)` / `### 2.1.0` に確定し、`package.json` の version を `2.1.0` に更新する。
- Breaking Change を 1 件含むが、ユーザー指示により SemVer の minor バンプとして `release/2.1.0` でリリースする。

## スコープ

### 対象

- spec / plan ファイルの作成 (`feature/release-2.1.0-spec` ブランチ上で commit)
- `release/2.1.0` ブランチの作成 (`develop` から worktree で分岐)
- `package.json` のバージョンを `2.0.1` → `2.1.0` に更新
- `CHANGELOG.md` 先頭の見出し `## X.Y.Z (YYYY/MM/DD)` を `## 2.1.0 (2026/05/24)` に確定 (配下の本文は変更しない)
- `README.md` / `README.ja.md` の `### X.Y.Z` (各ファイル内の What's New / Breaking Changes (仕様変更) セクション、計 4 箇所) を `### 2.1.0` に確定 (配下のバレット本文は変更しない)

### 対象外

- `develop` / `master` へのマージおよび PR 作成
- 実装コード (`src/*.ts`) の変更
- テストの追加・変更
- `CHANGELOG.md` / README 本文の項目追加・編集 (現状を確定するのみ。漏れがあれば別 feature ブランチで対応)
- `npm test` の実行・パッケージビルド・タグ付け・vsix 公開
- `package.json` の `engines.vscode` 更新 (本リリースで新しい VS Code API への依存追加は無いため `^1.110.0` を維持)

## ブランチ戦略

本リリース準備は 2 つのブランチに分けて進める。いずれも AGENTS.md の規約に従い `.worktrees/` 配下に worktree として作成する。

1. **`feature/release-2.1.0-spec`** (`.worktrees/release-2.1.0-spec/`)
   - `develop` から分岐
   - spec (本ファイル) と plan を順にコミットする
   - 完了後、AGENTS.md の merge-confirmation ルールに従いユーザー承認を経て `develop` に `--no-ff` で merge する
2. **`release/2.1.0`** (`.worktrees/release-2.1.0/`)
   - 上記 merge 後の `develop` から分岐
   - リリース準備の 3 コミット (後述) を積む

本 spec のスコープは上記 2 ブランチで完結する。これより先 (`develop` への戻しマージ、`master` への merge、タグ付け、vsix ビルド、Marketplace 公開) は本 spec のスコープ外。

## コミット構成

`release/2.1.0` に以下 3 コミットを順に積む。コミットは関心ごとに分割し、個別にレビュー可能にする (過去 2.0.0 / 2.0.1 と同じ形)。

### コミット 1: `chore: bump version to 2.1.0`

- `package.json` の `"version"` を `"2.0.1"` → `"2.1.0"` に更新する
- 他フィールド (`displayName`, `engines.vscode`, 依存関係など) は変更しない

### コミット 2: `docs: finalize 2.1.0 changelog entry`

- `CHANGELOG.md` 先頭の `## X.Y.Z (YYYY/MM/DD)` を `## 2.1.0 (2026/05/24)` に変更する
- 配下の Breaking Changes / Changes 本文は変更しない

### コミット 3: `docs: finalize READMEs for 2.1.0 release`

- `README.md` と `README.ja.md` の両方を一括で更新する
- 各ファイル内の `### X.Y.Z` (What's New / Breaking Changes (仕様変更) の 2 セクション、計 4 箇所) を `### 2.1.0` に変更する
- 本文 (各バレットの内容) は変更しない

## 変更内容の詳細

### `package.json`

```diff
-  "version": "2.0.1",
+  "version": "2.1.0",
```

### `CHANGELOG.md`

ファイル先頭の見出しのみ確定する。

```diff

+## 2.1.0 (2026/05/24)
```

```markdown
## 2.1.0 (2026/05/24)

### Breaking Changes

* Security hardening: Raw HTML in Markdown is now sanitized by default ...
  (markdown-pdf.sanitize, default "gfm")

### Changes

* Add markdown-pdf.sanitize setting
* Add ```plantuml fenced code block support [#92] [#162] [#389]
* Automatically download the latest Chrome Stable build (markdown-pdf.chromium.autoDownload)
* Add math rendering via KaTeX (markdown-pdf.math.enabled, markdown-pdf.math.katex.macros)
```

`### Fixes` セクションは無し (2.0.1 以降に develop へ追加された fix は存在しない。`fix(export): write intermediate HTML synchronously in exportHtml` は同セッション内で revert 済み)。

### `README.md`

What's New セクション (34行目付近) と Breaking Changes セクション (44行目付近) の見出しのみ確定する。

+### 2.1.0

-### X.Y.Z
+### 2.1.0
```

配下のバレット (3 件の What's New、1 件の Breaking) は変更しない。

## 確認事項 / 注意点

- `package.json` の `engines.vscode` は `^1.110.0` のまま据え置く。本リリースで新しい VS Code API への依存追加は無い。
- 実装フェーズで `feature/release-2.1.0-spec` を `develop` に merge する際、および将来 `release/2.1.0` を `develop` / `master` に統合する際は、AGENTS.md の merge-confirmation ルールに従いユーザー承認を待つ。
- `CHANGELOG.md` / README 本文の項目に漏れがあった場合は本 spec のスコープ外として扱い、別 feature ブランチで対応する。
- 実装は別セッションで `superpowers:executing-plans` 経由で進める前提。
- ブランチ・worktree の対応:
  - `feature/release-2.1.0-spec` → `.worktrees/release-2.1.0-spec/`
  - `release/2.1.0` → `.worktrees/release-2.1.0/`
