# release/2.0.0 リリース準備 設計書

## 目的

`develop` に積み上がった 175 コミットを 2.0.0 としてリリースするための準備作業 (バージョン更新・CHANGELOG 記載・README 更新) を行う。本作業のスコープは「リリース準備」までで、`develop` や `master` へのマージ・PR 作成は含まない。

## 背景

- 現行バージョンは `package.json` 上 `1.5.0`。最後に `master` にリリースされたのは 1.5.0。
- `develop` 上には `62ba914 Update: release 1.6.0` が存在するが、これは CHANGELOG と README のみを触ったもので、`package.json` のバージョンバンプを行っておらず、`master` へのマージも行われていない。結果として「準備だけされた 1.6.0」が develop に残っている状態。
- その後 `develop` には TypeScript 移行・esbuild バンドル・内製 `chromium-resolver` 導入・`markdown-it-include` / `markdown-it-named-headers` / `markdown-it-checkbox` のカスタム実装化・`cheerio` / `mustache` / `gray-matter` の削除・テスト基盤整備など、ユーザー影響を含む大規模変更が重ねられている。
- スコープと破壊的変更を含むことから、次のリリースはマイナーではなくメジャーバンプが妥当と判断し、1.6.0 を飛ばして 2.0.0 としてリリースする。

## スコープ

### 対象

- `release/2.0.0` ブランチの作成 (`develop` から分岐)
- `package.json` のバージョンを `2.0.0` に更新
- `CHANGELOG.md` に 2.0.0 エントリを追加 (Breaking Changes / Changes / Fixes)
- `README.md` / `README.ja.md` の以下セクション更新:
  - Specification Changes
  - Install / Chromium resolution
  - Configuration options の `markdown-pdf.executablePath` の説明
  - FAQ (新規 Q&A 追加)
  - Release Notes 抜粋
  - Special thanks
- Breaking Changes のユーザー向け明示 (CHANGELOG と FAQ の両方)

### 対象外

- `develop` / `master` へのマージおよび PR 作成
- 実装コード (`src/*.ts`) の変更
- テストの追加・変更
- `npm test` やパッケージビルドの実行 (最終動作確認はスコープ外)
- `CHANGELOG.md` の 1.6.0 以前のエントリの内容変更
- `README.md` の Features セクションの内容変更

## ブランチ戦略

- `develop` から `release/2.0.0` を作成する。
- 以降の全コミットは `release/2.0.0` 上に積む。
- このブランチから先 (develop への戻しマージ、master への PR、タグ付け、vsix ビルド、Marketplace 公開) は本 spec のスコープ外とする。

## 変更内容の詳細

### CHANGELOG.md — 2.0.0 エントリ構造

ファイル先頭に以下の構造で追加する。各項目の文言は実装時に最終化する。

```markdown
## 2.0.0 (2026/04/11)

### Breaking Changes

* Heading ID slug generation changed (GitHub-compatible VS Code 準拠)
  既存ドキュメント内のアンカーリンクが変化する可能性あり
* highlight.js を v9 → v11 にアップグレード
  一部のハイライトスタイル名が変更/削除。旧名は可能な範囲で新名にマッピングされ、
  マッピング不能時は `tomorrow.css` にフォールバック
* Front matter パーサーを内製実装に置換し、挙動を厳格化
  YAML sequence の front matter や非プレーンオブジェクト構造は拒否される
* Chromium のダウンロード / キャッシュ管理を内製 `chromium-resolver` に置換
  一時ディレクトリへの fallback を撤去し、VS Code の global storage 配下で管理

### Changes

* Migrate source code to TypeScript and bundle extension with esbuild
* Bundle `puppeteer-core` and manage Chromium via built-in `chromium-resolver`
  (installed Chrome/Edge を優先検出し、見つからなければ自動ダウンロード)
* Replace `markdown-it-include` / `markdown-it-named-headers` / `markdown-it-checkbox`
  with in-repo custom implementations
* Remove `cheerio` / `mustache` / `gray-matter` dependencies in favor of
  internal implementations
* Add unit and integration test suites (`vscode-test-cli`) including sample
  generation and HTML snapshot comparison
* Simplify VS Code variant detection and remove obsolete temp-cache fallback

### Fixes

* Fix global storage path resolution for Chromium cache
* Gracefully handle include errors in `markdown-it-include`
* Image `src` transformation now handles quoted attributes, flexible spacing,
  and raw-text contexts correctly
* Front matter parsing now handles BOM-prefixed files and rejects invalid
  structures
```

既存の 1.6.0 エントリおよびそれ以前はそのまま残す。

### README.md / README.ja.md

英語版と日本語版で同等の構成にする。日本語版の文言は既存の README.ja.md のトーンに合わせる。

#### 1. Specification Changes

既存セクションを 2.0.0 向けに書き換える。ユーザーが変更を意識する必要がある項目のみを端的に示し、詳細は FAQ に誘導する。

```markdown
## Specification Changes

Version 2.0.0 introduces changes that may affect existing behavior.
See the [FAQ](#faq) section for details.

- Heading IDs now follow GitHub-compatible VS Code slug generation.
  Existing internal anchors in your documents may change.
- Highlight.js upgraded from v9 to v11. Some highlight style names
  have been renamed or removed.
- Front matter parsing is now stricter. Some previously accepted
  formats may be rejected.
- Chromium is resolved from an installed Chrome/Edge browser first,
  or auto-downloaded on first use.
```

#### 2. Install / Chromium resolution

既存の Chromium ダウンロード説明を以下の形に簡潔化する。詳細な検出順序やダウンロードパスは FAQ に移す。

```markdown
## Install

### Chromium resolution

Markdown PDF uses a Chromium-based browser for PDF/PNG/JPEG export.
It tries the following sources in order:

1. The path specified in [markdown-pdf.executablePath](#markdown-pdfexecutablepath)
2. An installed Google Chrome, Microsoft Edge, or Chromium on your system
3. A managed Chromium automatically downloaded on first use

See [How is the Chromium browser selected?](#how-is-the-chromium-browser-selected)
and [Where is Chromium downloaded?](#where-is-chromium-downloaded) in the FAQ
for details.
```

#### 3. Configuration options — `markdown-pdf.executablePath`

既存の `markdown-pdf.executablePath` の説明 (README.md L387-394 付近, README.ja.md L378-385 付近) を、Microsoft Edge も指定可能であることを明示する形に更新する。あわせて Chromium の解決順序の詳細を FAQ に誘導するリンクを追加する。

更新後イメージ (英語版):

```markdown
#### `markdown-pdf.executablePath`
  - Path to a Chrome, Microsoft Edge, or Chromium executable to run instead of
    the bundled Chromium
  - See [How is the Chromium browser selected?](#how-is-the-chromium-browser-selected)
    in the FAQ for how this setting interacts with installed browser detection
    and the managed Chromium download
  - All `\` need to be written as `\\` (Windows)
  - To apply the settings, you need to restart Visual Studio Code

"markdown-pdf.executablePath": "C:\\Program Files (x86)\\Google\\Chrome\\Application\\chrome.exe"
```

日本語版は「バンドルされた Chromium の代わりに実行する Chrome, Microsoft Edge, または Chromium のパスを指定します」という形に書き換え、同じく FAQ へのリンクを追加する。

FAQ セクションのアンカーが日本語環境でも正しく解決できるようにする方針 (4. README.ja.md の扱い参照) に合わせること。

#### 4. FAQ

既存 FAQ セクションの末尾に以下 5 項目を新規追加する。見出しは Markdown の自動アンカー生成で Specification Changes や Install からリンクできるようにする。

- **`### Why did my heading anchors change?`**
  - 2.0.0 から `markdown-it-named-headers` を内製実装に置換したことと、heading ID の slug 生成が GitHub 互換の VS Code 準拠に変わったことを説明。
  - CJK や underscore の扱いが変わったこと、既存ドキュメント内の内部リンク (`#some-heading`) が切れる可能性があることに言及。

- **`### Why did my syntax highlight style stop working?`**
  - highlight.js が v9 → v11 にアップグレードされたことと、一部スタイル名が変更/削除されたことを説明。
  - 旧名は可能な範囲で新名にマッピングされ、マッピング不能な場合は `tomorrow.css` にフォールバックすること、警告メッセージが表示されること、設定の見直し方法を案内する。

- **`### Why is my front matter no longer parsed?`**
  - `gray-matter` を削除し内製実装に置換したことと、YAML sequence やプレーンでないオブジェクトの front matter を拒否するように厳格化したことを説明。
  - 対応する front matter の形式を例示する。

- **`### How is the Chromium browser selected?`**
  - Chromium の解決順序 (user setting → installed browser → managed download) を改めて説明。
  - 「installed browser」の検出については、Google Chrome (stable) が `@puppeteer/browsers` 経由で OS 標準のインストール場所から検出されること、Edge と Chromium は以下の固定パスをスキャンすることを説明。
  - OS 別の検出順序一覧 (優先順位順):

    **Windows**
    1. Google Chrome (stable install)
    2. `%LOCALAPPDATA%\Microsoft\Edge\Application\msedge.exe`
    3. `%LOCALAPPDATA%\Chromium\Application\chrome.exe`
    4. `%PROGRAMFILES%\Microsoft\Edge\Application\msedge.exe`
    5. `%PROGRAMFILES%\Chromium\Application\chrome.exe`
    6. `%PROGRAMFILES(X86)%\Microsoft\Edge\Application\msedge.exe`
    7. `%PROGRAMFILES(X86)%\Chromium\Application\chrome.exe`

    **macOS**
    1. Google Chrome (stable install)
    2. `/Applications/Chromium.app/Contents/MacOS/Chromium`
    3. `/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge`

    **Linux**
    1. Google Chrome (stable install)
    2. `/usr/bin/chromium-browser`
    3. `/usr/bin/chromium`
    4. `/usr/bin/microsoft-edge`
    5. `/usr/bin/microsoft-edge-stable`

  - 上記パスは `src/chromium-resolver.ts` の `getEdgeAndChromiumCandidates` と `getWindowsCandidates` (L54-98) から転記する。Chrome の具体パスは `@puppeteer/browsers` の内部仕様に依存するため README には列挙せず「OS 標準のインストール場所」とのみ記述する。

- **`### Where is Chromium downloaded?`**
  - インストール済みブラウザが見つからない場合、`@puppeteer/browsers` を使って Chromium を VS Code の global storage 配下にダウンロードすることを説明。
  - OS 別のダウンロードパス表:

    | OS | Download path |
    | --- | --- |
    | Windows | `%APPDATA%\Code\User\globalStorage\yzane.markdown-pdf\` |
    | macOS | `~/Library/Application Support/Code/User/globalStorage/yzane.markdown-pdf/` |
    | Linux | `~/.config/Code/User/globalStorage/yzane.markdown-pdf/` |

  - VS Code Insiders / VSCodium を使う場合は base path が `Code - Insiders` / `VSCodium` などに変わることに注記。
  - ダウンロード中は `Installing Chromium` が status bar に表示されること。

## 確認事項 / 注意点

- `CHANGELOG.md` の 2.0.0 エントリ本文の文言は実装フェーズで最終化する。本 spec は項目の粒度とカテゴリ分けを定義するにとどめる。
- Chromium 検出パスの記述は `src/chromium-resolver.ts` を実装時に再確認して正確性を担保すること。ソース側の変更を見落とさないよう、パスリストはコード (L54-98) からコピーする。
- `npm test` の実行・パッケージビルド・タグ付け・公開は本作業のスコープ外。リリース準備の成果物はブランチ `release/2.0.0` 上の 3 コミットまで。
- Breaking Changes の具体項目は上記 4 点 (slug / highlight.js / front matter / Chromium) を起点とし、CHANGELOG 本体執筆時に `git log master..release/2.0.0` を精査して追加があれば補う。
